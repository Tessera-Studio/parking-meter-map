### 15.2 お気に入り・保存した行き先（Pro）

**ボタンの場所**

- **カードの星（見せるだけ）**：カードの区間名のすぐ右に星を出す。登録していれば黒い★（`--ink` の塗り）、していなければ白い☆（白の塗り・`--ink` の線）。押しても何も起きない（カードを押したのと同じ）。カードのボタンは `[ ➤ ここへ行く ][ 詳細 ]` のまま。
- **詳細の☆**：お気に入りの登録・解除は、詳細（design-v2.md §7）の区間名の右の☆（丸）で行う。登録すると黒い★になり、カードの星も黒くなる。
- **右下の★ボタン**：タイマーのボタンの真上（間10px）に、同じ丸いボタン（48px・`--surface`・`--shadow-ctl`）。塗りの★のアイコン（`--ink`）、`aria-label="お気に入りの一覧"`。押すと一覧（下）を出す。右下は上から★・タイマー・現在地の3つ。

**右下の★ボタンを押したとき：お気に入りの一覧**

下からシートを出す（地図は暗くしない。シートは画面の高さの60%まで、中身が多いときはシートの中でスクロール。広い画面では右下に幅420px）。上の角丸24px、`--surface`、上に掴み手、右上に「×」。

```
お気に入り                                    ×
───────────────────────────────
[P] 霞が関一丁目        [19:00まで]       ★
    メーター · 現在地から 350m
[P] 有楽町二丁目        [あす 9:00から]    ★
    メーター · 現在地から 1.2km
───────────────────────────────
保存した行き先
[⚑] 歌舞伎座                               ★
```

- **区間の行**（高さ64px）：Pアイコン（状態の色）、区間名（16px/700）、バッジ（カードと同じ。いまの時刻で判定）、2行目に種類と距離（13px、`--muted`）。距離は現在地から（取れないときは「地図の中心から」）。1km以上は「1.2km」の形。
- **並び順**：緑を近い順、その後に赤とグレーを近い順（カードと同じ考え方）。
- **行を押す**：シートを閉じ、その区間を選び、地図をその区間に寄せ、カードの列をその区間のカードにする。
- **行の★を押す**：お気に入りから外す。行を消して、下に3秒「お気に入りから外しました　元に戻す」の札を出す。
- **保存した行き先の行**（高さ56px）：旗のアイコン・名前。押すとシートを閉じて行き先モード（design-v2.md §6）に入る。★で外せる（同じく「元に戻す」付き）。
- **何もないとき**：真ん中に小さく「詳細の☆を押すと、ここに並びます」。
- **上限**：区間50件、行き先10件。超えたら☆を押したときに「お気に入りは50件までです」の札。
- 赤・グレーの区間も一覧には全部出す（バッジで分かる）。

**行き先の保存**

- 行き先モード（design-v2.md §6）のカードの上の小札（「銀座四丁目の近く 12か所」）の右に☆。押すと保存。
- 保存した行き先は、一覧の下の段と、検索欄を押したときの候補の一番上（最大10件）に並ぶ。

**保存先**

`localStorage`：`pmm.favZones = [zoneId…]`（追加した順）、`pmm.favPlaces = [{name, title, lat, lng}…]`。区間のデータから消えた zoneId は、一覧に出さずに黙って捨てる。

### 15.6 購入と確認（App Store・StoreKit 2）

- プラグイン：**@capgo/native-purchases**（StoreKit 2。あとで Android の Google Play にも同じ形で対応できる）。サーバーは使わない。
- **持っているかの判定**：StoreKit の「いま有効な購入」（`Transaction.currentEntitlements`。Apple の署名を確かめたものだけ・返金されたものは入らない）に商品 ID があるか。
  - 起動時：前回の結果（`localStorage` の `pmm.pro.store`）ですぐ画面を出し、StoreKit で確かめ直す。オフラインでも判定できる。
  - ストアからの知らせ（`transactionUpdated`：ほかの端末での購入・返金・保護者の承認）でも確かめ直す。
- **購入**：「¥500で購入する」→ App Store の購入画面。
  - 成功：シートを閉じ、札「有料プランになりました。ありがとうございます」。鍵が外れる。
  - 自分でやめた：何も出さない（シートはそのまま）。
  - 承認待ち（ファミリー共有の「承認と購入のリクエスト」）：札「承認待ちです。承認されると、自動で使えるようになります」。
  - そのほかの失敗：札「購入できませんでした。通信状態を確かめて、もう一度お試しください」。
- アカウント登録はつくらない。同じ Apple ID なら、機種変更のあとも「購入の復元」で使える。
- 秘密情報はアプリにもリポジトリにも置かない（StoreKit 2 は端末の中で Apple の署名を確かめる）。

### 15.7 購入の復元

- 入口：有料プランのシートの「購入済みの方はこちら（復元）」、「？」のメニューの「購入の復元」。
- 押すと App Store の購入履歴と同期し（`AppStore.sync`。Apple ID のパスワードを聞かれることがある）、持っているか確かめ直す。
  - あった：シートを閉じ、札「有料プランを復元しました」。
  - なかった：札「この Apple ID での購入は見つかりませんでした」。
  - つながらない：札「App Store に接続できませんでした。もう一度お試しください」。

## 16. 広告（AdMob）

### 16.1 置く場所

| 画面 | 広告 |
|---|---|
| メインの地図・カードの列 | 画面の一番下にバナー（カード・右下のボタンはその分上に上がる） |
| 区間の詳細（design-v2.md §7） | 画面の一番下にバナー |
| タイマー（design-v2.md §9） | 画面の一番下にバナー |
| 「ここへ行く」のシート・有料プランのシート・お気に入りの一覧・ヘルプ | **出さない**（これらが上に開いたら、広告も隠す） |

- 有料プランでは出さない（広告の仕組み自体を動かさない）。

### 16.2 見た目

- **AdMob のアダプティブ・バナー**（画面の幅に合わせた横長。iPhone では高さ 50〜60px ほど）。ネイティブの表示で、画面の一番下（ホームバーの上）に重なる。
- バナーの高さは `--ad-h` に入れる。メイン画面のカードの列・右下のボタン・タイマーのカード・札は、その分だけ上に上げる。詳細のシートは下の余白を足し、中身がバナーに隠れないようにする（390px 幅のスマホでスクロールせずに収まる）。
- 動く広告・音の出る広告・全画面の広告は使わない（AdMob の管理画面の設定で切る）。
- シートの中の「広告を消す」のリンクは置かない（シートの高さを増やさないため）。有料プランへの入口は、鍵の付いたボタンとヘルプ。

### 16.3 仕組み

- プラグイン：**@capacitor-community/admob**（Google Mobile Ads SDK 入り）。
- 起動して、App Store で有料プランを持っていないと確かめ終えたら、初期化してバナーを出す（有料プランの人に一瞬でも出さないため）。上にシートが開いたら隠し、閉じたら出し直す。
- 設定（`config.js`）：`adsEnabled`、`admobBannerId`（バナーの広告ユニット ID）、`admobTesting`（テスト広告）。アプリ ID は `ios/App/App/Info.plist` の `GADApplicationIdentifier`（Android は `AndroidManifest.xml` の `com.google.android.gms.ads.APPLICATION_ID`）。
- **いまは Google のテスト用 ID**（アプリ ID `ca-app-pub-3940256099942544~1458002511`、バナー `ca-app-pub-3940256099942544/2435281174`）。本番は AdMob の管理画面で作った ID に替え、`admobTesting: false`。
- **トラッキングの許可（App Tracking Transparency）を求める**。初めて広告を出す前（無料の人が初めてアプリを開いたとき）に1回だけ。説明文（`Info.plist` の `NSUserTrackingUsageDescription`）は「あなたに合った広告を表示するために使います。許可しなくても、アプリはすべてお使いいただけます。」。許可されなければ、パーソナライズしない広告になる。有料プランの人には聞かない。
- `SKAdNetworkItems` は Google の ID だけ入れてある。本番の前に、Google の案内にある一覧をすべて足す。

## 22. データの出典と表示

警察のデータを加工して使っているので、どの都市も「元のデータ名・出典」と「加工して作成したこと」を書き、警察が作ったように見せない。

| 都市 | 元の利用条件 | 商用 | 画面の出典表示（詳細・このアプリについて） |
|---|---|---|---|
| 東京 | 東京都オープンデータ利用規約（CC BY 4.0） | 可 | 「警視庁のオープンデータ（東京都オープンデータカタログ）をもとに Tessera Studio が作成。CC BY 4.0」＋ライセンスへのリンク |

## 23. 販売・広告を始める手順

1. **シミュレーターで試す**：Xcode の StoreKit 設定ファイルに商品（`jp.tesseras.parkingmetermap.pro`・非消耗型・500円）を作り、スキームに設定する（手順は docs/app.md）。§21 を確かめる。
2. **App Store Connect**：アプリを登録し、「アプリ内課金」に同じ商品 ID で非消耗型の商品を作る（参照名「有料プラン」、価格 500円、表示名・説明）。「有料アプリ契約」（Paid Apps Agreement）・銀行口座・税の情報を済ませる。
3. **Sandbox で試す**：App Store Connect の「ユーザとアクセス → Sandbox」でテスト用の Apple ID を作り、実機で購入・復元を試す。
4. **法定ページ**：`docs/drafts/` の空欄を埋めて公開し、`config.js` の `legalPublished: true`。プライバシーポリシーの URL を App Store Connect に入れる。
5. **審査に出す**：アプリ内課金の商品も、アプリといっしょに審査に出す。
6. **広告（AdMob）**：AdMob に合同会社Tessera Studio 名義で登録し、iOS アプリと「バナー」の広告ユニットを作る。`Info.plist` の `GADApplicationIdentifier` と `config.js` の `admobBannerId` を本番の ID に替え、`admobTesting: false`。`SKAdNetworkItems` を Google の一覧どおりに足す。App Store Connect の「App のプライバシー」に、広告のためのデータ（デバイス ID・使用状況など）を申告する。アプリを公開したら、AdMob の管理画面で App Store のアプリとひもづけ、`app-ads.txt` を開発者サイトに置く。

ブラウザでの見た目の確認は、`config.js` を `proEnabled: false` にしたうえで `?preview=free`（無料の人）／`?preview=pro`（有料プランの人）を付けて開く（`?preview=off` で戻す）。
