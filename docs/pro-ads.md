## 14. 方針

- **地図と時間の表示は、ずっと無料。** 対応都市も全部無料で見られる。
- 収入は **Pro（買い切り）** と **小さな広告** の2本。予約駐車場への送客はしない。

### 15.2 お気に入り・保存した行き先（Pro）

**ボタンの場所**

- **カードの星（見せるだけ）**：カードの区間名のすぐ右に星を出す。登録していれば黒い★（`--ink` の塗り）、していなければ白い☆（白の塗り・`--ink` の線）。押しても何も起きない（カードを押したのと同じ）。カードのボタンは `[ ➤ ここへ行く ][ 詳細 ]` のまま。
- **詳細の☆**：お気に入りの登録・解除は、詳細（design-v2.md §7）の区間名の右の☆（丸）で行う。登録すると黒い★になり、カードの星も黒くなる。
- **右下の★ボタン**：タイマーのボタンの真上（間10px）に、同じ丸いボタン（48px・`--surface`・`--shadow-ctl`）。塗りの★のアイコン（`--ink`）、`aria-label="お気に入りの一覧"`。押すと一覧（下）を出す。右下は上から★・タイマー・現在地の3つ。

**右下の★ボタンを押したとき：お気に入りの一覧**

下からシートを出す（地図は暗くしない。シートは画面の高さの60%まで、中身が多いときはシートの中でスクロール。広い画面では右下に幅420px）。上の角丸24px、`--surface`、上に掴み手、右上に「×」。

```
お気に入り                                    ×
───────────────────────────────
[P] 霞が関一丁目        [19:00まで]       ★
    メーター · 現在地から 350m
[P] 有楽町二丁目        [あす 9:00から]    ★
    メーター · 現在地から 1.2km
───────────────────────────────
保存した行き先
[⚑] 歌舞伎座                               ★
```

- **区間の行**（高さ64px）：Pアイコン（状態の色）、区間名（16px/700）、バッジ（カードと同じ。いまの時刻で判定）、2行目に種類と距離（13px、`--muted`）。距離は現在地から（取れないときは「地図の中心から」）。1km以上は「1.2km」の形。
- **並び順**：緑を近い順、その後に赤とグレーを近い順（カードと同じ考え方）。
- **行を押す**：シートを閉じ、その区間を選び、地図をその区間に寄せ、カードの列をその区間のカードにする。
- **行の★を押す**：お気に入りから外す。行を消して、下に3秒「お気に入りから外しました　元に戻す」の札を出す。
- **保存した行き先の行**（高さ56px）：旗のアイコン・名前。押すとシートを閉じて行き先モード（design-v2.md §6）に入る。★で外せる（同じく「元に戻す」付き）。
- **何もないとき**：真ん中に小さく「詳細の☆を押すと、ここに並びます」。
- **上限**：区間50件、行き先10件。超えたら☆を押したときに「お気に入りは50件までです」の札。
- 赤・グレーの区間も一覧には全部出す（バッジで分かる）。

**行き先の保存**

- 行き先モード（design-v2.md §6）のカードの上の小札（「銀座四丁目の近く 12か所」）の右に☆。押すと保存。
- 保存した行き先は、一覧の下の段と、検索欄を押したときの候補の一番上（最大10件）に並ぶ。

**保存先**

`localStorage`：`pmm.favZones = [zoneId…]`（追加した順）、`pmm.favPlaces = [{name, title, lat, lng}…]`。区間のデータから消えた zoneId は、一覧に出さずに黙って捨てる。

### 15.6 決済と購入の確認（サーバー側）

**ホスティング**：Cloudflare Pages（画面のファイル）＋ Pages Functions（下の API、`functions/api/`）＋ Workers KV（発行の回数・回数制限）。アカウント登録はつくらない。独自ドメインを取って Pages に設定する（AdSense の申し込みに必要。§16.3）。

**Stripe アカウント**：日本の法人（合同会社Tessera Studio）として作成し、入金は円建ての法人口座。明細に出る表記（statement descriptor）は「TESSERA STUDIO」など、利用者が見て分かるものにする。Stripe のサポート用メールアドレスも support@tesseras.jp にする（領収メールに載る）。

- `POST /api/checkout` → Stripe Checkout Session を作って URL を返す。`success_url` は `/?pro=success&sid={CHECKOUT_SESSION_ID}`、`cancel_url` は `/`。メールアドレスは Stripe 側で必ず入力してもらう。
- `GET /api/verify?sid=…` → Stripe でその Session が支払い済みか確かめ、**購入証（ライセンス）** を返す。
  - 中身：`{v:1, pid:<購入ID>, iat:<発行日時>}` を ECDSA P-256 で署名したもの（`base64url(JSON).base64url(署名)`）。
  - 秘密鍵は Pages の環境変数（シークレット）だけに置く。公開鍵は `config.js` に置く。
- `POST /api/restore {email}` → そのメールで支払い済みの Session を Stripe から探し、あれば購入証を返す。
- 1つの購入につき発行は**端末5台まで**（KV に `n:<購入ID>` → 発行回数）。超えたら「発行できる台数の上限に達しました。support@tesseras.jp までお問い合わせください」。
- 復元は、同じ IP からは**1分に3回まで**（KV で数える）。

**クライアント側**（`pro.js`）：

- 購入証を `localStorage` の `pmm.pro` に保存し、起動時に WebCrypto で署名を確かめる（オフラインでも判定できる）。
- 署名が正しければ Pro。壊れている・消えているときは無料に戻すだけで、エラーは出さない。
- `?pro=success` で戻ってきたら `/api/verify` を呼び、成功したら小さな札「有料プランになりました。ありがとうございます」を3秒出して、URL のクエリを消す。
- 秘密情報（Stripe のキーなど）はクライアントに置かない。

## 16. 広告

### 16.1 置く場所

| 画面 | 広告 |
|---|---|
| メインの地図・カードの列・検索 | **出さない** |
| 「ここへ行く」のシート・購入シート・お気に入りの一覧・このアプリについて | **出さない** |
| 区間の詳細（design-v2.md §7） | シートの一番下（地図アプリの2行の下）に1枠 |
| タイマー（design-v2.md §9） | 「メーター・チケットに表示された時刻が優先です」の下に1枠 |

### 16.2 見た目

- 枠：横幅いっぱい、広告の高さ **100px で固定**（読み込み前から場所をとっておき、画面がずれないようにする）。`--surface-2` 地、角丸 `--r-btn`。
- 枠の左上に小さく「広告」（11px、`--muted`）。
- 枠の下に文字リンク「広告を消す（有料プラン）」（13px、`--muted`、右寄せ）。
- 広告が読み込めなかったときは、枠を空のまま残す（中身で画面が動かないように）。
- 動く広告・音の出る広告・全画面の広告は使わない（広告ネットワークの設定で切る）。

### 16.3 読み込み

- 広告ネットワークは **Google AdSense**。審査が通るまでは枠を出さない（`adsEnabled: false`）。
- 申し込みの前に：独自ドメインで公開、プライバシーポリシー（§18）を公開、`/ads.txt` を置ける状態にしておく。AdSense の支払い先も合同会社Tessera Studio の名義にそろえる。
- 広告のスクリプトは、詳細かタイマーを初めて開いたときに読み込む。メイン画面の表示を遅くしない。
- Pro のときはスクリプト自体を読み込まない。

## 23. 販売・広告を始める手順

1. **鍵を作る**：`node scripts/pro-keys.mjs`。出てきた秘密鍵（`PRO_PRIVATE_JWK`）は手順3のシークレットにだけ入れ、ファイルに保存しない。公開鍵は `config.js` の `proPublicKey` に貼る。
2. **Stripe**：法人アカウントで、商品「パーキング・メーター・マップ Pro」に 480円・一回払いの価格を作り、価格 ID（`price_…`）を控える。まずテストモードで。
3. **Cloudflare Pages**：このリポジトリをつなぐ（ビルドなし、出力はリポジトリの一番上）。環境変数（シークレット）に `STRIPE_SECRET_KEY`・`STRIPE_PRICE_ID`・`PRO_PRIVATE_JWK`、KV の名前空間を `PRO_KV` で紐づける。独自ドメインを設定する。
4. **確認**：テストモードのまま `config.js` の `proEnabled: true` にして、§21 を確かめる。
5. **法定ページ**：`docs/drafts/` の2つの空欄を埋め、一番上に移して `build/stamp.py` を実行。
6. **本番**：Stripe を本番のキー・価格 ID に替える。
7. **広告**：AdSense の審査が通ったら、`config.js` に `adsenseClient`・広告枠の ID を入れ、`adsEnabled: true`。`/ads.txt` を置く。

販売前の見た目は、`?preview=free`（無料の人）／`?preview=pro`（Pro の人）で確かめられる（`?preview=off` で戻す。販売を始めると効かない）。
