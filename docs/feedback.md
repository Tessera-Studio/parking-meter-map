# ご意見・不具合の受け付けと仕分け

利用者の声を、**1つの Google スプレッドシート**に集めて、**週1回まとめて仕分ける**。入口はいくつあっても、届く先はこのシートだけにする（漏れを防ぐため）。

```
アプリのフォーム ──→ Apps Script（Web アプリ）──→ スプレッドシート「フィードバック」
                                              └→ メール通知（不具合・区間の誤りだけ）
support@tesseras.jp へのメール ──→ 週1回、手でシートに1行足す（入口：メール）
App Store のレビュー ──────────→ 週1回、手でシートに1行足す（入口：App Store）
```

## 1. アプリの入口

| 入口 | 場所 | 自動で付くもの |
|---|---|---|
| ご意見・不具合を送る | ⓘ（ヘルプ）の「購入の復元」の下 | アプリの版・iOS の版（端末の情報）・プラン |
| 区間情報の訂正 | 詳細の一番下（出典の下） | 上に加えて、区間番号・区間名・都道府県。種類は「区間情報の訂正」が選ばれた状態 |

フォームの中身：種類（不具合／区間情報の訂正／要望／その他）、内容（1000文字まで）、返信先のメールアドレス（任意）。スクリーンショットは受け取らない（地図に自宅付近が写ることがあるため）。現在地は送らない。

送り先は `config.js` の `feedbackUrl`（2026-11-20 に設定。スプレッドシート「メーターマップ フィードバック」の Apps Script）。空にしたときは、「送る」でメールアプリが開き、同じ内容を support@tesseras.jp あてに送る。

いまのシート：[メーターマップ フィードバック](https://docs.google.com/spreadsheets/d/1UUsJPxU8HJuSyqYIxHmXNfSGGx6DDd6VzEehNaLxTOA/edit)（見られるのは共有された人だけ）

## 2. スプレッドシートの用意（最初に1回）

1. Google ドライブで、新しいスプレッドシートを作る（名前の例：「メーターマップ フィードバック」）。support@tesseras.jp を見られるアカウントで作るとよい。
2. メニューの **拡張機能 → Apps Script** を開く。
3. はじめからある `コード.gs` の中身をすべて消し、このリポジトリの `tools/feedback/Code.gs` の中身を貼り付けて保存（💾）。
4. 上の関数の選び方で **setup** を選び、▶「実行」。初回は「権限を確認」→ 自分のアカウント →「詳細」→「（安全ではないページ）に移動」→「許可」。スプレッドシートに「フィードバック」シートと見出しができる。
5. 右上の **デプロイ → 新しいデプロイ** → 種類の歯車で **ウェブアプリ** を選ぶ。
   - 説明：メーターマップ フィードバック
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
6. 「デプロイ」→ 出てきた **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーして、Claude に渡す（`config.js` の `feedbackUrl` に入れる）。
7. 毎週のまとめ：左の時計のアイコン（トリガー）→「トリガーを追加」→ 関数 **weeklyReport**、イベント「時間主導型」→「週ベース」→ 月曜日・午前8〜9時。

Apps Script を直したときは、**デプロイ → デプロイを管理 → 鉛筆 → バージョン「新バージョン」→ デプロイ**（URL は変わらない）。

## 3. シートの列

| 列 | 中身 |
|---|---|
| 受付日時・入口・種類・内容・返信先・区間番号・区間名・都道府県・アプリの版・プラン・端末・端末番号 | 自動で入る（メールと App Store の分は手で入れる） |
| 状態 | 新規 → 確認済み → 対応予定 → 対応済み ／ 対応しない（選ぶだけ） |
| 優先度 | P1・P2・P3。自動で目安が入る（区間の誤り P1、不具合 P2、要望・その他 P3）。仕分けで直す |
| 担当・対応した版・メモ | 仕分けと対応のときに書く。「対応しない」は理由をメモに書く。直した PR があれば URL もメモに |

- 端末番号は、送りすぎを防ぐためだけの、アプリを入れたときに作るランダムな番号。名前やメールとは結びつけない。
- 送りすぎの制限：1台から10分に5件まで、全体で1分に30件まで。

## 4. 仕分けの決まり

| 優先度 | 中身 | いつまでに |
|---|---|---|
| P1 | 起動しない・課金の不具合・区間の情報の誤り（時間・料金・場所） | メール通知が来たその日のうちに確認 |
| P2 | 使いにくい・表示の崩れ・そのほかの不具合 | 次の版で直す |
| P3 | 要望・その他 | 月1回まとめて検討 |

**週1回30分（月曜の朝。毎週のまとめのメールが届いたら）**
1. メールと App Store のレビューで届いたものを、シートに1行ずつ足す（入口を選ぶ）。
2. 「新規」を上から見て、状態と優先度を付ける。**新規をゼロにする**のが決まり。
3. 同じ話がいくつもあるときは、1件目を残し、ほかはメモに「重複：○行目」と書いて「対応しない」に。
4. 対応したら「対応済み」にし、返信先があれば一言返す。直したことは App Store の「新機能」の欄にも書く。

**毎週見る数字**（毎週のまとめのメールに出る）：新規の件数、未対応の件数（うち P1）、未対応で一番古いものの日数、種類ごとの件数。

## 5. Claude に頼めること

- シートの「新規」を読んで、似た報告をまとめ、直し方の案とプルリクエストを作る。区間の情報の誤りは、データの修正まで進める。
- 毎週の件数の推移をまとめる。

（Claude がシートを読むには、シートの URL を渡し、Google のアカウントで読める状態にしておく。）

## 6. プライバシー

- フォームの内容・返信先のメールアドレス（任意）・アプリの版・端末の情報を、当社の Google スプレッドシートに保存する（プライバシーポリシー「6. ご意見・お問い合わせ」）。
- App Store の「App のプライバシー」に、「ユーザコンテンツ（カスタマーサポート）」「連絡先情報：メールアドレス（任意・カスタマーサポート・ユーザに紐づく）」を足す（docs/appstore.md §5）。
